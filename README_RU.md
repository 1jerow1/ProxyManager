# Proxy Manager (Windows)

Небольшой GUI для запуска sing-box через TUN: через прокси идут только выбранные программы, остальной трафик — напрямую.

## Что умеет
- Подключение через SOCKS5 или HTTP-прокси (IP, порт, логин, пароль).
- Вставка строки прокси целиком: `host:port:логин:пароль`, `логин:пароль@host:port` или `socks5://логин:пароль@host:port` — поля заполнятся сами.
- Проверка прокси перед запуском: сервер недоступен, неверный порт или тип прокси, неверный логин или пароль — сообщается сразу, а не после запуска туннеля.
- Выбор программ, которые работают через прокси: Google Chrome, VS Code, Hermes и любые другие `.exe`. Программы узнаются по полному пути, а не по имени файла.
- Kill switch: если sing-box упадёт, выбранные программы остаются без интернета, а не уходят в сеть напрямую.
- Запуск, остановка и переподключение sing-box одной кнопкой.
- Отслеживание sing-box: если он упадёт, программа покажет причину из лога и уведомление в трее.
- Проверка внешнего IPv4 через api.ipify.org: отдельно для выбранных программ и для остальных.
- Сворачивание окна в системный трей. Цвет значка показывает состояние: серый — отключено, жёлтый — идёт подключение, зелёный — подключено.
- Раздельное сохранение настроек HTTP и SOCKS5 в settings.json с переключением профилей.

## Требования
- Windows 10/11 x64.
- Python 3.11 или новее.
- Права администратора для TUN/маршрутов.
- Windows amd64 версия sing-box.
- SOCKS5- или HTTP-прокси с доступом из вашей сети. HTTP-прокси не передаёт UDP; SOCKS5-серверу для UDP-зависимых приложений нужна поддержка UDP ASSOCIATE.

## Установка
1. Распакуйте архив в `D:\Oleg\ProxyManager` или другую папку без ограничений доступа.
2. Скачайте официальный Windows amd64 архив sing-box: https://github.com/SagerNet/sing-box/releases
3. Поместите `sing-box.exe` в `bin\sing-box.exe`.
4. Откройте PowerShell в папке проекта:
   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   python main.py
   ```
5. При запросе UAC разрешите запуск от имени администратора. Программа с правами администратора запускается через `pythonw.exe`, без отдельного окна консоли.
6. Выберите тип прокси, введите IP/домен, порт, логин и пароль. Можно вставить строку прокси от провайдера целиком в поле «Сервер» — она разберётся на поля, когда вы перейдёте к другому полю.
7. Отметьте программы в строке «Через прокси» и нажмите «Подключить».
8. После подключения строка IP покажет два адреса: «Выбранные программы» (адрес прокси) и «Остальные программы» (ваш обычный адрес).
9. TUN направляет трафик выбранных программ через прокси автоматически. Не задавайте отдельный прокси в настройках Chrome. Для HTTP-профиля у выбранных программ блокируются IPv6 и UDP, так как HTTP-прокси поддерживает только TCP.

## Выбор программ
Программа узнаётся по полному пути к `.exe`, а не по имени: `chrome.exe` из другой папки (например, Chromium от Playwright или Gologin) через прокси не пойдёт. Пути ищутся при каждом подключении.
- **Google Chrome** — `chrome.exe` из папки установки Google Chrome (`...\Google\Chrome\Application\`); путь берётся из реестра и стандартных папок.
- **VS Code** — вся папка установки VS Code (берётся из реестра, стандартных папок или запущенного `Code.exe`) и все программы из папки расширений `%USERPROFILE%\.vscode\extensions`. Туда входят Claude Code (`claude.exe`) и Codex (`codex.exe`): они ходят в сеть отдельными процессами, а не через `Code.exe`.
- **Hermes** — все программы из папки `%LOCALAPPDATA%\hermes`. `Hermes.exe` из `hermes-agent\apps\desktop\release\win-unpacked` — только окно приложения: запросы к нейросетям делает фоновый процесс `hermes serve`, который работает на встроенном Python Hermes (`hermes\tools\python-…\python.exe`). Его встроенные node, Chromium, git и uv тоже лежат в этой папке и идут через прокси.
- **Другие программы** — через запятую: полный путь к `.exe` (`C:\Program Files\App\app.exe`), путь к папке (через прокси пойдут все программы из неё) или просто имя (`telegram.exe`). Имя при подключении превращается в полный путь: берутся запущенные сейчас программы с таким именем и путь из реестра Windows. Если путь не найден, подключение не начнётся — запустите программу или впишите полный путь. Переменные вида `%LOCALAPPDATA%` раскрываются.
- Команды, запущенные во встроенном терминале VS Code (например, `claude`, `git`, `npm`), — это отдельные программы. Они не входят в группу VS Code; при необходимости добавьте их в «Другие программы». Так же и с Hermes: системные программы, которые агент запускает из папки Windows или Program Files (например, `powershell.exe`, `curl.exe`), в группу Hermes не входят.
- Выбор сохраняется в settings.json. Изменения применяются при следующем подключении: если прокси уже подключён, нажмите «Переподключить».

## Kill switch
Галочка «Kill switch» (включена по умолчанию). Через Windows Filtering Platform — движок, на котором работает брандмауэр Windows, — выбранным программам запрещается выходить в интернет мимо TUN-интерфейса sing-box:
- пока sing-box работает, их трафик идёт через TUN и запрет его не касается;
- если sing-box упал, был убит или не запустился при переподключении, программы остаются без интернета, а не уходят в сеть с вашим настоящим IP;
- заодно закрывается утечка через WebRTC: браузер не может отправить пакет в интернет с адреса физического адаптера даже при работающем прокси;
- локальная сеть (192.168.x.x, 10.x.x.x и т. п.) остаётся доступной;
- запрет сохраняется после перезагрузки Windows: пока вы не нажмёте «Подключить» или «Отключить», выбранные программы без интернета. Это работает, даже если выключен брандмауэр Windows.

В WFP нельзя запретить папку целиком — только конкретные `.exe`. Поэтому для Hermes, VS Code и папок из «Других программ» список `.exe` собирается в фоне после подключения (это занимает от нескольких секунд до минуты) и кэшируется в `logs\programs-cache.json`. Кроме того, каждые 5 секунд в запрет добавляются только что запущенные программы из выбранных папок. Подключение от этого не замедляется: фильтры ставятся и снимаются одной транзакцией за доли секунды.

Пока kill switch держит программы без интернета, статус в окне — «Нет прокси — программы заблокированы», значок в трее красный. Чтобы вернуть прокси, нажмите «Подключить». Чтобы программы снова ходили напрямую, нажмите «Отключить» — kill switch снимется. Фильтры видны командой `netsh wfp show filters` (в имени — «Proxy Manager kill switch»).

## Отключение и выход
- Кнопка «Отключить» останавливает sing-box и снимает kill switch: программы снова ходят в сеть напрямую.
- Пока прокси подключён, кнопка «Подключить» называется «Переподключить»: она перезапускает sing-box с текущими настройками.
- Закрытие окна прячет программу в трей.
- Пункт «Выход» останавливает sing-box, снимает kill switch и завершает программу.
- Если sing-box не удаётся остановить, приложение покажет ошибку и останется открытым. PID sing-box сохраняется для восстановления туннеля после аварийного закрытия приложения: при следующем запуске программа подхватит работающий sing-box.
- Повторный запуск программы, пока она уже работает, просто открывает её окно.

## Логи
- `logs\sing-box.log` — лог sing-box. По умолчанию в него пишутся только предупреждения и ошибки. Чтобы видеть каждое соединение и путь программы, которая его открыла, добавьте в settings.json `"verbose_log": true` и переподключитесь; учтите, что такой лог растёт примерно на 10 МБ в час.
- Если лог больше 5 МБ, при подключении он переименовывается в `sing-box.old.log`, и начинается новый.
- `logs\app.log` — внутренние ошибки самой программы.
- `logs\programs-cache.json` и `logs\kill-switch-state.json` — найденные `.exe` и список программ под kill switch.
- Кнопка «Открыть лог» открывает лог sing-box.

## Важные ограничения
- Это стартовый проект, а не проверенная на всех сетевых конфигурациях VPN-замена.
- Если kill switch выключен, при аварийном завершении sing-box трафик выбранных программ пойдёт напрямую. С kill switch защищены все `.exe`, найденные в выбранных папках при последнем сканировании, и всё, что из них запускалось; программа, которая появилась в папке после сканирования и впервые запущена при упавшем sing-box, может успеть выйти в сеть напрямую до 5 секунд, пока Proxy Manager её не заметит.
- HTTP-прокси работает через HTTP CONNECT и не передаёт UDP. В HTTP-режиме UDP выбранных программ отклоняется, чтобы браузеры переключались с QUIC на TCP; UDP-зависимые функции выбранных программ (например, звонки) через прокси работать не будут. Остальные программы это не затрагивает. Для SOCKS5 UDP сервер должен поддерживать UDP ASSOCIATE.
- DNS-запросы всех программ, включая выбранные, идут на DNS-серверы вашего сетевого адаптера напрямую, а не через прокси. Адреса сайтов, к которым обращаются выбранные программы, видны вашему DNS-провайдеру. DNS работает только по IPv4.
- Программа распознаётся по пути к `.exe`. Если программа ходит в сеть через вспомогательный процесс из другой папки, добавьте его путь в «Другие программы».
- Текущая проверка IP проверяет внешний адрес только через HTTPS-запрос; это не полноценный аудит утечек DNS/IPv6.
- Пароль сохраняется в settings.json открытым текстом. Не используйте на общем компьютере; для постоянного использования перенесите секрет в Windows Credential Manager.
- Перед использованием обновите sing-box до актуальной стабильной версии и проверьте конфиг командой:
  `bin\sing-box.exe check -c configs\proxy.json`
- При ошибке смотрите `logs\sing-box.log` и `logs\app.log`.

## Устранение неполадок
- «Не найден sing-box.exe»: проверьте путь `bin\sing-box.exe`.
- «Сервер не отвечает как HTTP-прокси / SOCKS5-прокси»: выбран не тот тип прокси или порт. У многих провайдеров HTTP и SOCKS5 работают на разных портах.
- «Прокси отклонил логин или пароль»: проверьте учётные данные в личном кабинете провайдера. Некоторые провайдеры авторизуют по IP-адресу и не проверяют пароль вовсе.
- «Не ответил за 8 секунд» или «отклонил подключение»: прокси недоступен из вашей сети, или указан неверный адрес или порт.
- Ошибка конфигурации: выполните команду проверки из раздела выше и проверьте лог.
- `configure tun interface: ... already exists / Element not found / device ... is not functioning`: Windows не успела удалить TUN-адаптер прошлого запуска sing-box — так бывает, если sing-box был убит, а не остановлен (через Диспетчер задач, `taskkill /F`, при аварии). Proxy Manager останавливает sing-box мягко (Ctrl+Break), а при такой ошибке сам повторяет запуск до 3 раз.
- Нет доступа к интернету: отключите sing-box, проверьте доступность прокси-сервера и совместимость его UDP.
- Окно не появляется: запустите программу ещё раз — откроется окно уже запущенного экземпляра. Или найдите значок в области уведомлений Windows.
- Программа закрылась без сообщения: смотрите `logs\app.log`.
